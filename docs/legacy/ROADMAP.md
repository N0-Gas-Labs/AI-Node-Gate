# Year-One Delivery Roadmap (legacy)

> **Status: historical intent.** This is the delivery roadmap the prior organization set
> for its first year. It is preserved as memory of prior intent. This hub's own
> [`ROADMAP.md`](../ROADMAP.md) supersedes it for current work.

The roadmap was written as four quarters, each with a single plain-English exit
criterion — a test of whether the quarter had actually succeeded, rather than a list of
activities that could be declared "done" without changing anything for a user.

## Q1 — Make the portfolio understandable

Map the repositories, label each one, preserve history, reconcile EvidenceOS, and flag
the public prototype clearly. **Exit:** the owner can point to one official repository
per active lane.

## Q2 — Make one flagship genuinely usable

One complete visitor journey on the public front door; basic automated checks; no real
payments or credentials in the public prototype. **Exit:** an unfamiliar person can use
it and describe its purpose.

## Q3 — Turn the strongest supporting lane into a demonstrator

Default choice: the Podcast Operations Suite. Build the minimum pieces for one real
source→output transformation. **Exit:** the output is something a real user would value.

## Q4 — Consolidate and decide

Measure use, archive what has no purpose, document the lessons, and choose
continue / pivot / stop for each lane. **Exit:** every active repository has a purpose, a
next milestone, a risk, and a reason to exist.

## Monthly review ritual

Each month, the same six questions were asked, in order:

1. What changed for users?
2. What was tested, and what failed?
3. Is there one official repository per lane?
4. Is there any secret, payment, wallet, or financial-claim risk?
5. Should each project stop, continue, or be promoted?
6. What is the single next decision the owner must make?

## CTO decision gates

The team could proceed on its own with documentation, tests, local prototypes, and
reversible commits. It had to pause for the owner before: deleting or archiving anything
on GitHub, connecting real payments or wallets, spending money, publishing new financial
claims, or changing a flagship lane.

## What carried forward

The ritual — *measure, decide, record* — is the same instinct that produced this hub's
signed, hash-chained decision ledger. The roadmap's discipline of naming a single exit
criterion per phase, and of pausing at explicit gates, is the ancestor of the gate this
hub is built around.
